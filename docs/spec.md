## 1. コンセプト

本・漫画・アニメ・映画・ドラマを **1つのアプリでまとめて記録** し、
「どれだけ読んだか・観たか」をグラフで振り返れる個人向け記録アプリ。
（Studyplus の記録・可視化部分のイメージ。SNS 機能はなし）

- 想定ユーザー: 1人（ログイン機能なし）
- 一言コンセプト（仮）: 「あなたの“好き”を、ジャンルを越えて記録・可視化」

## 2. 技術構成

**フロント（画面）もバックエンド（データ・集計）も Python で書く。** HTML/CSS/JS は書かない。

| 項目 | 採用 | 理由 |
|---|---|---|
| 言語 | Python 3.11+ | グラフや外部 API 連携のライブラリが豊富 |
| 画面 | Streamlit | Python だけで画面・フォーム・グラフが作れる。ブラウザで動くので PC でもスマホでも開ける |
| データ保存 | JSON ファイル | 中身を目で確認でき、デモ用データも手で書ける。1ユーザーなら性能も十分 |
| グラフ | Plotly（Streamlit 標準対応） | ホバー表示などデモ映えする |
| 集計 | pandas | 月別・カテゴリ別の集計が数行で書ける |

> **JSON の読み書きは `storage.py` に集約し、他のファイルからは直接 JSON を触らない。**
> こうしておけば、後で SQLite に乗り換えたくなっても `storage.py` だけ直せば済む。

### HTML ではなく Streamlit にした理由

- HTML＋JS にすると、画面とは別に API サーバー（FastAPI など）と通信処理が必要になり、ハッカソンの期間では完成度を上げにくい
- Streamlit も最終的にはブラウザ上の HTML として表示されるので、スマホのブラウザから使える（画面幅が狭いと列は縦に並ぶ）
- デザインの自由度は HTML より低いが、今回は記録とグラフが主役なので十分

### スマホから使う方法（デモ用）

| 方法 | 手順 | 注意 |
|---|---|---|
| ① 同じ Wi-Fi から開く（**推奨**） | PC で `streamlit run app.py --server.address 0.0.0.0` → スマホで `http://<PC の IP>:8501` を開く | 一番確実。データは PC の `data/` に保存される |
| ② Streamlit Community Cloud に公開 | GitHub のリポジトリを連携してデプロイ | 再起動すると保存したデータが消える。デモ用データはリポジトリに入れておく |

## 3. 用語

| 用語 | 意味 | 誰が決めるか |
|---|---|---|
| **カテゴリ** | 本 / 漫画 / アニメ / 映画 / ドラマ / その他（固定 6 種） | 開発側で固定 |
| **タグ** | ジャンルタグ（ミステリー・SF など）と感情タグ（泣ける・笑えるなど）の 2 種類。1 記録に複数付けられる | テンプレートを開発側で用意し、ユーザーが自由に追加 |
| **作品の項目** | 出版社・掲載誌・制作会社。1 記録に 1 つずつ（タグとは別） | ユーザー（本・漫画の出版社は ISBN から自動入力） |
| **記録** | 1 作品を読み終えた・観終えた 1 回分のデータ | ユーザー |

### 記録のルール

- **読了・視聴完了したときに 1 回だけ記録する**（途中経過の記録は今回は対象外。§9 の Could を参照）
- **1 記録 = 1 作品**。作品数・冊数・本数は記録の件数で数える
- **同じ作品を 2 回読んだ・観た場合は、別の記録として登録する**（グラフの量が正しくなるため）
- **「その他」** は上の 5 カテゴリに当てはまらないもの（舞台・ゲーム・音楽ライブなど）。数・量の集計からは外し、カテゴリ別件数のグラフにだけ入れる

## 4. 集計（「数」と「量」）

全カテゴリ（その他を除く）について、**「数」と「量」の 2 種類** で集計する。
ダッシュボードの切り替え（**数 / 量**）で表示するグラフを変える。選んだ値は `settings.json` に保存する。
**単位の違うもの（ページと分、冊と話など）は同じグラフに混ぜない。**

| カテゴリ | 入力項目 | 数 | 量 |
|---|---|---|---|
| 本 | ページ数 | 冊数（記録の件数） | ページ数 |
| 漫画 | ページ数 と 巻数（**少なくとも一方は必須**） | 巻数 | ページ数 |
| 映画 | 上映時間（分） | 本数（記録の件数） | 時間（分） |
| アニメ | 話数、1 話あたりの分数（既定 24 分） | 作品数（記録の件数） と 話数 | 時間（話数 × 分数） |
| ドラマ | 話数、1 話あたりの分数（既定 45 分） | 作品数（記録の件数） と 話数 | 時間（話数 × 分数） |
| その他 | なし | 集計しない | 集計しない |

### グラフに使う単位

| 切り替え | グラフ | 単位 | 中身 |
|---|---|---|---|
| 量 | 月別 読書量 | ページ | 本・漫画 |
| 量 | 月別 視聴時間 | 分（表示は時間でもよい） | 映画・アニメ・ドラマ |
| 数 | 月別 読んだ冊数 | 冊 | 本の冊数 ＋ 漫画の巻数 |
| 数 | 月別 観た作品数 | 作品 | 映画の本数 ＋ アニメ・ドラマの作品数 |
| 数 | 月別 話数 | 話 | アニメ・ドラマ |

漫画は「ページ数」と「巻数」の片方だけ入力されていることがある。
グラフに必要な値が入っていない記録はそのグラフの集計から外し、「値が未入力の記録が N 件あります」と表示する。

## 5. タグと作品の項目

### 5.1 タグ（ジャンル・感情）

| 種類 | `kind` | 例（テンプレート） | 画面での扱い |
|---|---|---|---|
| ジャンルタグ | `genre` | ミステリー、SF、ファンタジー、恋愛、ホラー、アクション、日常、歴史、ノンフィクション、ビジネス・自己啓発 | 感情タグと **並べて表示** する |
| 感情タグ | `emotion` | 泣ける、笑える、熱い、癒される、怖い、考えさせられる、ワクワクする | ジャンルタグと並べて表示する |

- テンプレートは初期データとして `data/tags.json` に入れておく（`is_template: true`）
- ユーザーは記録の追加画面・タグ管理画面から自由にタグを追加できる
- タグには **表示するカテゴリ**（`categories`）を持たせ、カテゴリごとに出すタグを分ける（例: 「ビジネス・自己啓発」は本だけ）。`["all"]` は全カテゴリ

### 5.2 表記ゆれ対策

自由記入を許すと「感動系」と「泣ける」のように同じ意味のタグが別々にできてしまう。次の 3 つで防ぐ。

1. **入力は「選ぶ」を基本にする**: 既存のタグを候補として先に出し、無いときだけ新しく作る（`st.multiselect` の新しい値を許すオプションを使う。対応バージョンは実装前に確認する）
2. **登録時に正規化する**: 全角・半角や前後の空白をそろえ（`unicodedata.normalize("NFKC", ...)` ＋ `strip()`）、正規化後に同じ名前のタグが同じ種類にあれば新しく作らず既存のタグを使う
3. **タグの統合**: タグ管理画面で「泣ける」を「感動系」に統合すると、各記録の `tag_ids` が書き換わり、統合元のタグは削除される

### 5.3 作品の項目（出版社・掲載誌・制作会社）

1 作品に基本 1 つなので、タグではなく記録の項目として持つ。

| 項目 | フィールド | 対象カテゴリ | 入力方法 |
|---|---|---|---|
| 出版社 | `publisher` | 本・漫画 | ISBN から自動入力。手入力のときは過去の値を候補に出す |
| 掲載誌 | `magazine` | 漫画 | 手入力。過去の値を候補に出す |
| 制作会社 | `studio` | 映画・アニメ・ドラマ | 手入力。過去の値を候補に出す |

- 保存時にタグと同じ正規化をかける
- 「過去の値を候補に出す」ことで表記ゆれを減らす

## 6. データ設計

### 6.1 ファイル構成

```
data/
├── records.json   # 記録の一覧
├── tags.json      # タグの一覧（テンプレート＋ユーザーが作ったもの）
├── settings.json  # 表示設定（数 / 量 の切り替えなど）
└── images/        # ユーザーがアップロードした表紙画像
```

### 6.2 records.json

```json
[
  {
    "id": "3f2a9c1e-...",
    "category": "anime",
    "title": "葬送のフリーレン",
    "creator": "山田鐘人（原作）",
    "publisher": null,
    "magazine": null,
    "studio": "マッドハウス",
    "image": { "type": "upload", "value": "data/images/3f2a9c1e-....jpg" },
    "tag_ids": ["t-003", "t-101"],
    "rating": 5,
    "review": "静かなのに泣ける。",
    "finished_on": "2026-09-30",
    "metrics": { "episodes": 28, "minutes_per_episode": 24 },
    "created_at": "2026-10-17T14:05:00+09:00",
    "updated_at": "2026-10-17T14:05:00+09:00"
  }
]
```

| 項目 | 型 | 必須 | 説明 |
|---|---|---|---|
| id | 文字列 | ○ | `uuid4` で自動採番 |
| category | 文字列 | ○ | `book` / `manga` / `anime` / `movie` / `drama` / `other` |
| title | 文字列 | ○ | 作品タイトル |
| creator | 文字列 | | 作者・監督など |
| publisher | 文字列 | | 出版社（本・漫画のみ） |
| magazine | 文字列 | | 掲載誌（漫画のみ） |
| studio | 文字列 | | 制作会社（映画・アニメ・ドラマのみ） |
| isbn | 文字列 | | ISBN-13（本・漫画のみ。ハイフンなし） |
| image | オブジェクト | | `type`: `url`（外部取得） / `upload`（ユーザー画像） / `none`。`value`: URL またはファイルパス |
| tag_ids | 文字列の配列 | | tags.json の id を参照 |
| rating | 整数 1〜5 | | 評価（星） |
| review | 文字列 | | 感想 |
| finished_on | 日付 `YYYY-MM-DD` | ○ | 読了日・視聴完了日。**グラフはこの日付で集計** |
| metrics | オブジェクト | ○ | カテゴリごとに中身が変わる（下表） |
| created_at / updated_at | 日時 | ○ | 自動で入れる |

対象カテゴリ以外の `publisher` / `magazine` / `studio` / `isbn` は `null` にする。

**metrics の中身**

| カテゴリ | 中身 | 備考 |
|---|---|---|
| book | `{ "pages": 320 }` | |
| manga | `{ "pages": 192, "volumes": 1 }` | どちらか一方は省略可（両方省略は不可） |
| movie | `{ "minutes": 124 }` | |
| anime / drama | `{ "episodes": 12, "minutes_per_episode": 24 }` | |
| other | `{}` | 集計しないので空 |

### 6.3 tags.json

```json
[
  { "id": "t-001", "name": "ミステリー", "kind": "genre", "categories": ["all"], "color": "#64B5F6", "is_template": true },
  { "id": "t-010", "name": "ビジネス・自己啓発", "kind": "genre", "categories": ["book"], "color": "#A1887F", "is_template": true },
  { "id": "t-101", "name": "泣ける", "kind": "emotion", "categories": ["all"], "color": "#E57373", "is_template": true }
]
```

| 項目 | 説明 |
|---|---|
| id | `t-` ＋ 連番。記録側は **タグ名ではなく id を持つ** → タグ名を変えても記録が壊れない |
| name | タグ名（正規化済み） |
| kind | `genre` / `emotion` |
| categories | 表示するカテゴリの配列。`["all"]` は全カテゴリ |
| color | グラフ・チップの色 |
| is_template | テンプレートなら `true`。テンプレートも名前変更・削除できる |

- タグを削除したら、各記録の `tag_ids` からも取り除く
- タグを統合したら、統合元の id を統合先の id に置き換え（重複は 1 つにまとめ）、統合元を削除する

### 6.4 settings.json

```json
{ "metric_mode": "amount" }
```

| 項目 | 値 | 既定 |
|---|---|---|
| metric_mode | `amount`（量） / `count`（数） | `amount` |

## 7. 表紙画像とメタデータ

### 7.1 表紙画像

| 方法 | 内容 |
|---|---|
| ① 外部から取得 | 本・漫画は ISBN から取得した表紙の URL を保存 |
| ② アップロード | ユーザーの画像を `data/images/<記録id>.<拡張子>` に保存 |
| ③ なし | カテゴリごとの既定アイコン（📚 📖 📺 🎬 🎞️ 🎫）を表示 |

### 7.2 メタデータ（タイトル・ページ数など）

| カテゴリ | 方法 | 理由 |
|---|---|---|
| 本・漫画 | **ISBN を入力して openBD から取得**（API キー不要、日本の本に強い）。取得できない項目は手入力 | 入力の手間が大きく減る。漫画はページ数が入っていないことがあるので手入力で補う |
| 映画・アニメ・ドラマ | **手入力**（Studyplus の学習時間入力と同じ考え方） | 入力する数字が少ない（映画は時間 1 つ、アニメ・ドラマは話数だけで分数は既定値あり）。API キー登録やクレジット表記の手間を省く |
| その他 | 手入力 | |

- 外部 API が落ちていても手入力で記録できるようにしておく
- 再視聴・再読用に「前の記録をコピーして追加」を用意する（§9 の Should）
- 映像作品の外部取得（TMDB / AniList）は時間があれば追加する（§9 の Could）

## 8. 画面

| # | 画面 | 主な内容 |
|---|---|---|
| 1 | **ダッシュボード**（トップ） | 今月の読書ページ数・視聴時間・記録件数、グラフ、最近の記録、**数 / 量** と期間の切り替え |
| 2 | **記録を追加** | カテゴリを選ぶと、そのカテゴリ用の入力欄（ページ数 / 巻数 / 時間 / 話数、出版社 / 掲載誌 / 制作会社）とタグ候補に切り替わる。本・漫画は ISBN 入力で自動入力。表紙画像のアップロード |
| 3 | **記録一覧** | 表紙＋タイトルのカード表示。カテゴリ・タグ・期間・キーワードで絞り込み |
| 4 | **記録の詳細・編集** | 全項目の表示、編集、削除、「この記録をコピーして追加」 |
| 5 | **タグ管理** | ジャンル・感情に分けて表示。タグの追加・名前変更・色変更・表示カテゴリの変更・削除・**統合** |

### グラフ（ダッシュボード）

| グラフ | 形 | 表示条件 | 内容 |
|---|---|---|---|
| 月別 読書量 | 積み上げ棒 | 量 | 本・漫画のページ数 |
| 月別 視聴時間 | 積み上げ棒 | 量 | 映画・アニメ・ドラマの時間 |
| 月別 読んだ冊数 | 積み上げ棒 | 数 | 本の冊数・漫画の巻数 |
| 月別 観た作品数 | 積み上げ棒 | 数 | 映画・アニメ・ドラマの作品数 |
| 月別 話数 | 積み上げ棒 | 数 | アニメ・ドラマの話数 |
| カテゴリ別 件数 | 横棒 | 常に | 何をいくつ記録したか（**その他も含む**） |
| タグ別 件数 | 横棒 | 常に | ジャンル・感情を分けて表示。好みの傾向がわかる |

期間は「今年 / 過去 12 か月 / 全期間」から選べるようにする。

## 9. 優先度

| 優先度 | 機能 |
|---|---|
| **Must**（1 日目夕方まで） | 記録の追加・一覧・削除（JSON 保存）、カテゴリ別の入力欄切り替え（その他を含む 6 種）、出版社・掲載誌・制作会社の入力 |

| **Won't**（今回はやらない） | ログイン、SNS 機能、スマホアプリ（スマホはブラウザから使う） |

## 11. フロントとバックエンドの分担

### 境界のルール

- **フロントは JSON を直接触らず、集計の計算もしない**（`storage.py` / `stats.py` / `external_api.py` の関数を呼ぶだけ）
- **バックエンドは画面の処理（`st.` で始まるもの）を書かない**
- 入力チェックの正しさはバックエンドが責任を持つ（ルール違反は `ValueError` を投げる）。フロントはそのメッセージを画面に出す

### やること一覧

| 分類 | フロント | バックエンド |
|---|---|---|
| 記録 | カテゴリに応じた入力欄の切り替え、エラーメッセージの表示、一覧・詳細・編集・削除の画面 | 必須項目・カテゴリ別の項目のチェック、保存・更新・削除、id と日時の自動付与 |
| タグ | 候補から選ぶ／新しく作る入力欄、ジャンルと感情を並べた表示、タグ管理画面（統合を含む） | 名前の正規化、重複チェック、カテゴリ・種類での絞り込み、統合（`tag_ids` の書き換え）、削除時の参照の除去 |
| 出版社・掲載誌・制作会社 | 過去の値を候補に出す入力欄 | 値の正規化、過去の値の一覧を返す |
| 集計 | 数 / 量・期間の切り替え、Plotly でのグラフ描画、未入力件数の表示 | 月別・カテゴリ別・タグ別の集計（その他を数・量から除外）を DataFrame で返す、未入力件数を数える |
| 外部データ | ISBN の入力欄、取得結果をフォームに反映 | openBD からの取得。失敗したら `None` を返す（画面を止めない） |
| 画像 | アップロード欄、表紙・既定アイコンの表示 | `data/images/` への保存、記録削除時の画像削除 |
| 設定 | 切り替えの UI | `settings.json` の読み書き |

### 役割分担（フロント 2 人・バックエンド 1 人）

| 担当 | 役割 | 主な担当ファイル | 主な仕事 |
|---|---|---|---|
| **A** | フロント①（入力系） | `pages/1_記録を追加.py`、`pages/2_記録一覧.py`、`components.py` | 追加フォーム（カテゴリ別の入力欄・タグ選択・項目の候補表示・ISBN 入力）、表紙アップロード、一覧・詳細・編集・削除・コピーして追加 |
| **B** | フロント②（可視化系）＋ PM・発表 | `app.py`、`pages/3_タグ管理.py`、`data/*.json`（デモ用データ・タグのテンプレート）、`docs/` | ダッシュボードとグラフ描画（数 / 量の切り替え）、タグ管理画面（統合を含む）、進捗管理、デモ用データ作成、スライド・デモ動画 |
| **C** | バックエンド | `storage.py`、`stats.py`、`external_api.py` | データの保存・読み込み・入力チェック・正規化、集計処理、ISBN からの取得 |

#### この分け方にした理由

- 画面は数が多いので 2 人で分ける。**入力する画面（A）と見る画面（B）** に分けると、触るファイルが重ならない
- B はグラフを描くだけで集計は C が担当するため、画面の作業量が A より少ない。空いた分を PM・発表準備に充てる
- C はデータの形と関数を一手に持つので、仕様がブレにくい

#### 並行して作業するための進め方

1. **1 日目の最初に、下の関数の名前・引数・戻り値を 3 人で確定する**（このファイルに追記）
2. C は `storage.py` を最優先で作る（A・B 両方が使うため）。目標は 1 日目の昼
3. それまで A・B は `data/records.json` に手書きしたサンプルデータを使って画面を作る
4. C の関数ができたら差し替える

### 関数の取り決め（たたき台）

**storage.py**

| 関数 | 説明 |
|---|---|
| `load_records() -> list[dict]` | 全記録を返す |
| `get_record(record_id) -> dict \| None` | 1 件返す |
| `add_record(data: dict) -> str` | 入力チェック・正規化をして、id・日時を自動で付けて保存し、id を返す。ルール違反は `ValueError` |
| `update_record(record_id, data: dict) -> None` | 更新（入力チェックあり、`updated_at` を自動更新） |
| `delete_record(record_id) -> None` | 削除（アップロード画像も削除） |
| `load_tags(category=None, kind=None) -> list[dict]` | タグを返す。`category` を指定するとそのカテゴリに表示するタグだけ、`kind` で `genre` / `emotion` に絞る |
| `add_tag(name, kind, categories, color) -> str` | 名前を正規化して追加し、id を返す。同じ種類に同名があれば既存の id を返す |
| `update_tag(tag_id, name, color, categories) -> None` | タグを更新 |
| `delete_tag(tag_id) -> None` | タグを削除し、各記録の `tag_ids` からも取り除く |
| `merge_tags(source_id, target_id) -> None` | `source_id` のタグを `target_id` に統合し、`source_id` を削除 |
| `list_field_values(field, category=None) -> list[str]` | `publisher` / `magazine` / `studio` の過去の値を、よく使う順に返す |
| `save_image(record_id, uploaded_file) -> str` | 画像を `data/images/` に保存し、パスを返す |
| `load_settings() -> dict` / `save_settings(settings: dict) -> None` | 表示設定の読み書き |

**stats.py**（いずれも pandas の DataFrame を返し、B が Plotly で描画する。`other` は数・量の集計に含めない）

| 関数 | 説明 |
|---|---|
| `monthly_pages(records, period)` | 月 × カテゴリ（本・漫画）のページ数 |
| `monthly_minutes(records, period)` | 月 × カテゴリ（映画・アニメ・ドラマ）の視聴時間（分） |
| `monthly_books(records, period)` | 月 × カテゴリの本の冊数・漫画の巻数 |
| `monthly_works(records, period)` | 月 × カテゴリ（映画・アニメ・ドラマ）の作品数 |
| `monthly_episodes(records, period)` | 月 × カテゴリ（アニメ・ドラマ）の話数 |
| `missing_count(records, period, metric_mode) -> int` | 選んだ集計に必要な値が未入力の記録の件数 |
| `count_by_category(records, period)` | カテゴリ別件数（**その他を含む**） |
| `count_by_tag(records, tags, period)` | タグ別件数（`kind` 列でジャンル・感情を区別） |
| `this_month_summary(records)` | 今月のページ数・視聴時間・件数 |

`period` は `"this_year"` / `"last_12_months"` / `"all"` のいずれか。
