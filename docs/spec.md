## 1. コンセプト

本・漫画・アニメ・映画・ドラマを **1つのアプリでまとめて記録** し、
「どれだけ読んだか・観たか」をグラフで振り返れる個人向け記録アプリ。
（Studyplus の記録・可視化部分のイメージ。SNS 機能はなし）

- 想定ユーザー: 1人（ログイン機能なし）
- 一言コンセプト（仮）: 「あなたの“好き”を、ジャンルを越えて記録・可視化」

---

## 2. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| 言語 | Python 3.11+ | グラフや外部 API 連携のライブラリが豊富 |
| 画面 | Streamlit | Python だけで画面・フォーム・グラフが作れる。HTML/CSS 不要 |
| データ保存 | JSON ファイル | 中身を目で確認でき、デモ用データも手で書ける。1ユーザーなら性能も十分 |
| グラフ | Plotly（Streamlit 標準対応） | ホバー表示などデモ映えする |
| 集計 | pandas | 月別・カテゴリ別の集計が数行で書ける |

> **JSON の読み書きは `storage.py` に集約し、他のファイルからは直接 JSON を触らない。**
> こうしておけば、後で SQLite に乗り換えたくなっても `storage.py` だけ直せば済む。

## 3. 用語

| 用語 | 意味 | 誰が決めるか |
|---|---|---|
| **カテゴリ** | 本 / 漫画 / アニメ / 映画 / ドラマ（固定 5 種） | 開発側で固定 |
| **タグ** | 感動系・ミステリー・SF など自由な分類。1 記録に複数付けられる | ユーザーが自由に作成 |
| **記録** | 1 作品を読み終えた・観終えた 1 回分のデータ | ユーザー |

### 記録のルール

- **読了・視聴完了したときに 1 回だけ記録する**（途中経過の記録は今回は対象外。§8 の Could を参照）
- **同じ作品を 2 回読んだ・観た場合は、別の記録として登録する**（グラフの量が正しくなるため）

---

## 4. カテゴリごとの「量」の扱い

グラフにするため、カテゴリごとに量の単位を決める。
**単位の違うもの（ページと分）は同じグラフに混ぜない。**

| カテゴリ | 入力項目 | グラフ上の単位 | 計算 |
|---|---|---|---|
| 本 | ページ数 | ページ | そのまま |
| 漫画 | ページ数 と 巻数（**両方入力できる。少なくとも一方は必須**） | ページ または 巻（ユーザーが選択） | そのまま |
| 映画 | 上映時間（分） | 分 | そのまま |
| アニメ | 話数 × 1 話あたりの分数（既定 24 分） | 分 | 話数 × 分数 |
| ドラマ | 話数 × 1 話あたりの分数（既定 45 分） | 分 | 話数 × 分数 |

→ グラフは **「読書量（ページ）」** と **「視聴時間（分）」** の 2 系統に分ける。

### 漫画の集計単位

ダッシュボードで「漫画の集計単位」を **ページ / 巻** から選べる。選んだ値は `settings.json` に保存する。

| 選択 | グラフでの扱い |
|---|---|
| ページ（既定） | 本と一緒に「読書量（ページ）」グラフに積み上げる |
| 巻 | 「読書量（ページ）」は本のみ。別に「漫画（巻）」グラフを表示する |

選んだ単位の値が入っていない記録はグラフの集計から外し、「単位未入力の記録が N 件あります」と表示する。

## 5. データ設計

### 5.1 ファイル構成

```
data/
├── records.json   # 記録の一覧
├── tags.json      # ユーザーが作ったタグの一覧
├── settings.json  # 表示設定（漫画の集計単位など）
└── images/        # ユーザーがアップロードした表紙画像
```

### 5.2 records.json

```json
[
  {
    "id": "3f2a9c1e-...",
    "category": "anime",
    "title": "葬送のフリーレン",
    "creator": "山田鐘人（原作）",
    "image": { "type": "url", "value": "https://.../cover.jpg" },
    "tag_ids": ["t-001", "t-004"],
    "rating": 5,
    "review": "静かなのに泣ける。",
    "finished_on": "2026-09-30",
    "metrics": { "episodes": 28, "minutes_per_episode": 24 },
    "created_at": "2026-10-17T14:05:00+09:00",
    "updated_at": "2026-10-17T14:05:00+09:00"
  }
]
```

| 項目 | 型 | 必須 | 説明 |
|---|---|---|---|
| id | 文字列 | ○ | `uuid4` で自動採番 |
| category | 文字列 | ○ | `book` / `manga` / `anime` / `movie` / `drama` |
| title | 文字列 | ○ | 作品タイトル |
| creator | 文字列 | | 作者・監督・制作会社など |
| image | オブジェクト | | `type`: `url`（外部取得） / `upload`（ユーザー画像） / `none`。`value`: URL またはファイルパス |
| tag_ids | 文字列の配列 | | tags.json の id を参照 |
| rating | 整数 1〜5 | | 評価（星） |
| review | 文字列 | | 感想 |
| finished_on | 日付 `YYYY-MM-DD` | ○ | 読了日・視聴完了日。**グラフはこの日付で集計** |
| metrics | オブジェクト | ○ | カテゴリごとに中身が変わる（下表） |
| created_at / updated_at | 日時 | ○ | 自動で入れる |

**metrics の中身**

| カテゴリ | 中身 | 備考 |
|---|---|---|
| book | `{ "pages": 320 }` | |
| manga | `{ "pages": 192, "volumes": 1 }` | どちらか一方は省略可（両方省略は不可） |
| movie | `{ "minutes": 124 }` | |
| anime / drama | `{ "episodes": 12, "minutes_per_episode": 24 }` | |

### 5.3 tags.json

```json
[
  { "id": "t-001", "name": "感動系", "color": "#E57373" },
  { "id": "t-004", "name": "ファンタジー", "color": "#64B5F6" }
]
```

- 全カテゴリ共通で使う（「ミステリー」は本でも映画でも同じタグを使える）
- 記録側は **タグ名ではなく id を持つ** → タグ名を変えても記録が壊れない
- タグを削除したら、各記録の `tag_ids` からも取り除く

### 5.4 settings.json

```json
{ "manga_unit": "pages" }
```

| 項目 | 値 | 既定 |
|---|---|---|
| manga_unit | `pages` / `volumes` | `pages` |

## 6. 表紙画像（アイコン）

| 方法 | 内容 |
|---|---|
| ① 外部から取得 | タイトルで検索 → 候補を表示 → 選んだ画像の URL を保存 |
| ② アップロード | ユーザーの画像を `data/images/<記録id>.<拡張子>` に保存 |
| ③ なし | カテゴリごとの既定アイコン（📚 📖 📺 🎬 🎞️ など）を表示 |

**外部 API 候補**（いずれも無料。表紙だけでなくページ数・時間なども取れるので、入力の手間が減る）

| カテゴリ | API | API キー |
|---|---|---|
| 本 | Google Books API / openBD（日本の書籍に強い） | 不要（Google は任意） |
| 漫画・アニメ | AniList GraphQL API / Jikan API | 不要 |
| 映画・ドラマ | TMDB API | **必要（登録が必要なので初日に取得する）** |

> MVP では **①はまず 1 カテゴリだけ**（例: 本 = Google Books）に対応し、残りは時間があれば追加する。
> 外部 API が落ちていても ②③ で記録できるようにしておく。

## 7. 画面

| # | 画面 | 主な内容 |
|---|---|---|
| 1 | **ダッシュボード**（トップ） | 今月の読書ページ数・視聴時間・記録件数、グラフ、最近の記録、漫画の集計単位の切り替え |
| 2 | **記録を追加** | カテゴリを選ぶと、そのカテゴリ用の入力欄（ページ数 / 巻数 / 時間 / 話数）に切り替わる。表紙画像の検索・アップロード |
| 3 | **記録一覧** | 表紙＋タイトルのカード表示。カテゴリ・タグ・期間・キーワードで絞り込み |
| 4 | **記録の詳細・編集** | 全項目の表示、編集、削除 |
| 5 | **タグ管理** | タグの追加・名前変更・色変更・削除 |

### グラフ（ダッシュボード）

| グラフ | 形 | 内容 |
|---|---|---|
| 月別 読書量 | 積み上げ棒 | 本（＋漫画の集計単位がページのときは漫画）のページ数を月ごとに |
| 月別 漫画（巻） | 棒 | 漫画の集計単位が巻のときだけ表示 |
| 月別 視聴時間 | 積み上げ棒 | アニメ・映画・ドラマの時間を月ごとに |
| カテゴリ別 件数 | 横棒 | 何をいくつ記録したか |
| タグ別 件数 | 横棒 | 自分の好みの傾向がわかる |

期間は「今年 / 過去 12 か月 / 全期間」から選べるようにする。

## 8. 優先度

| 優先度 | 機能 |
|---|---|
| **Must**（1 日目夕方まで） | 記録の追加・一覧・削除（JSON 保存）、カテゴリ別の入力欄切り替え |
| **Must**（2 日目午前まで） | 月別グラフ（読書量・視聴時間）、漫画の集計単位の切り替え、タグの作成と付与、表紙画像のアップロード |
| **Should** | 外部 API で表紙取得（1 カテゴリ）、絞り込み検索、記録の編集 |
| **Could** | 途中経過の記録（「今日 50 ページ読んだ」）、外部 API を全カテゴリ対応、タグ別グラフ、年間まとめ画面 |
| **Won't**（今回はやらない） | ログイン、SNS 機能、スマホアプリ |

## 10. 役割分担（フロント 2 人・バックエンド 1 人）

| 担当 | 役割 | 主な担当ファイル | 主な仕事 |
|---|---|---|---|
| **A** | フロント①（入力系） | `pages/1_記録を追加.py`、`pages/2_記録一覧.py`、`components.py` | 追加フォーム（カテゴリ別の入力欄切り替え・入力チェック）、表紙の検索・アップロード UI、一覧・詳細・編集・削除 |
| **B** | フロント②（可視化系）＋ PM・発表 | `app.py`、`pages/3_タグ管理.py`、`data/*.json`（デモ用データ）、`docs/` | ダッシュボードとグラフ描画、タグ管理画面、進捗管理、デモ用データ作成、スライド・デモ動画 |
| **C** | バックエンド | `storage.py`、`stats.py`、`external_api.py` | データの保存・読み込み、集計処理、外部 API 連携 |

### この分け方にした理由

- 画面は数が多いので 2 人で分ける。**入力する画面（A）と見る画面（B）** に分けると、触るファイルが重ならない
- B はグラフを描くだけで集計は C が担当するため、画面の作業量が A より少ない。空いた分を PM・発表準備に充てる
- C はデータの形と関数を一手に持つので、仕様がブレにくい

### 並行して作業するための進め方

1. **1 日目の最初に、下の関数の名前・引数・戻り値を 3 人で確定する**（このファイルに追記）
2. C は `storage.py` を最優先で作る（A・B 両方が使うため）。目標は 1 日目の昼
3. それまで A・B は `data/records.json` に手書きしたサンプルデータを使って画面を作る
4. C の関数ができたら差し替える

### フロントとバックエンドの取り決め（たたき台）

**storage.py**

| 関数 | 説明 |
|---|---|
| `load_records() -> list[dict]` | 全記録を返す |
| `get_record(record_id) -> dict \| None` | 1 件返す |
| `add_record(data: dict) -> str` | id・日時を自動で付けて保存し、id を返す |
| `update_record(record_id, data: dict) -> None` | 更新（`updated_at` を自動更新） |
| `delete_record(record_id) -> None` | 削除（アップロード画像も削除） |
| `load_tags() -> list[dict]` | 全タグを返す |
| `add_tag(name, color) -> str` | タグを追加し、id を返す |
| `update_tag(tag_id, name, color) -> None` | タグを更新 |
| `delete_tag(tag_id) -> None` | タグを削除し、各記録の `tag_ids` からも取り除く |
| `save_image(record_id, uploaded_file) -> str` | 画像を `data/images/` に保存し、パスを返す |
| `load_settings() -> dict` / `save_settings(settings: dict) -> None` | 表示設定の読み書き |

**stats.py**（いずれも pandas の DataFrame を返し、B が Plotly で描画する）

| 関数 | 説明 |
|---|---|
| `monthly_reading(records, period, manga_unit)` | 月 × カテゴリのページ数（と漫画の巻数） |
| `monthly_watching(records, period)` | 月 × カテゴリの視聴時間（分） |
| `count_by_category(records, period)` | カテゴリ別件数 |
| `count_by_tag(records, tags, period)` | タグ別件数 |
| `this_month_summary(records)` | 今月のページ数・視聴時間・件数 |

`period` は `"this_year"` / `"last_12_months"` / `"all"` のいずれか。

**external_api.py**

| 関数 | 説明 |
|---|---|
| `search(category, query) -> list[dict]` | 候補の一覧。各要素は `{ "title", "creator", "image_url", "metrics" }`。失敗時は空のリストを返す（画面を止めない） |
