# コンテンツ記録 — 初期実装

Python 3.11以降・Streamlit・JSONで作成した個人向けアプリです。ホームとカテゴリ別集計を中心に、記録・編集・コピー・削除・検索・タグ管理をつないでいます。

## 起動

このフォルダーを開いて、次の順に実行してください。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Pythonコマンドが見つからない場合は、Python 3.11以降をインストールしてください。固定ナビゲーションにStreamlitの標準機能`st.bottom`を使うため、指定バージョンで起動します。

スマートフォンから同じWi-Fi経由で使う場合：

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 0.0.0.0
```

表示されたネットワークURLをスマートフォンで開きます。ファイアウォールの許可が必要になる場合があります。保存先は起動したPCです。ログインのない個人用アプリのため、公開サーバーにそのまま配置する構成ではありません。

## 作成した機能

- ホーム：日付ごとの記録、表紙・カテゴリ・数量・感想。上部に新規追加ボタンを重複配置しません。
- 下部固定ナビゲーション：ホーム／羽ペンの記録／集計／検索。入力・編集時は非表示です。
- 記録：6カテゴリに応じた数量・作品情報、画像、ジャンル／感情タグ。評価欄はありません。
- 集計：6カテゴリごとのカード。期間・数／量の切り替え、未入力件数、カテゴリへの遷移。
- カテゴリ詳細：記録ごとの表示。本・漫画は「読んだページ数÷その記録の総ページ数」の進捗バー。ページ数はバー下で右揃え、パーセント表示はありません。
- カテゴリごとの月別グラフ：詳細内で任意に開きます。ページ・分などの単位は混ぜません。
- 検索：タイトル・感想・作品情報、カテゴリ、タグのAND条件、記録日の範囲。
- 詳細：編集・削除確認・別記録としてのコピー。再読をタイトルで自動統合しません。
- タグ管理：追加・名前／色／対象カテゴリ変更・削除・同じ種類内の統合。
- ISBN手入力によるopenBD取得：取得失敗でも手入力を継続可能。取得結果の明示操作で空欄だけ補完します。

`data/records.json`は空で開始します。ホームの「サンプルで画面を確認する」から架空の9記録を追加できます。既存の記録を上書きする操作はありません。サンプルの日付はデザインに合わせて2026年9〜10月です。他の年に確認する場合は集計期間を「全期間」にしてください。

## ファイル構成と担当境界

```text
app.py                  画面・遷移・入力状態
components.py           記録カード・下部固定ナビゲーション

storage.py              JSON・画像保存、検証、正規化、タグ参照更新
stats.py                期間抽出・カテゴリ／月別／タグ別集計・表示用数量
external_api.py         ISBNの検証と外部取得
data/records.json       利用者の記録
data/tags.json          タグ・テンプレート
data/settings.json      数／量の設定
data/demo_records.json  明示的に読み込むサンプル
data/images/            アップロード表紙（保存時に作成）
docs/spec.md            会話で更新されたv0.5仕様
```

あなたの担当であるフロント②の中心は、`app.py`の`home`・`statistics`・`category_detail`・`tag_management`です。バックエンドが未配置の作業フォルダーだったため、動作をつなぐ保存・集計処理も実装しています。フロントはJSONを直接読み書きしません。他担当の実装と統合する際は`docs/spec.md`の関数契約を確認してください。

## 進捗と集計

- `metrics.pages`：その記録で現在までに読んだ累計ページ数。
- `metrics.total_pages`：その本の総ページ数。任意ですが、進捗バーには必要です。
- 300／500ページならバーの約6割を着色します。総ページ数が不明ならバーを表示せず、未登録と明記します。
- 途中の読書は同じ記録を編集します。編集前の300と編集後の400を足して700とは数えません。
- 再読はコピー等で新しい記録を作ります。
- 数モードの本は読了済みの冊数、量モードは途中の記録も含めた読んだページ数です。カテゴリの件数には途中の記録も含みます。
- 日付は`recorded_on`。途中記録の`finished_on`はnullです。読了時は`finished_on`に記録日が入ります。
- 月別集計は各記録の記録日への計上です。編集前後のページ差分を日別に保存する学習ログ方式ではありません。
- 漫画の数は読了済み記録の入力巻数。アニメ・ドラマの数は作品数と話数を別表示します。「その他」は数／量の集計対象外です。

## 保存とバックアップ

保存先はアプリと同じフォルダー内の`data/`です。JSONはUTF-8で保存します。別の保存先を使う場合は環境変数`CONTENT_RECORDS_DATA_DIR`を指定します。

JSONは一時ファイルから置き換え、読み込み・更新にはファイルロックを使います。壊れたJSONを空のデータで上書きしません。複数ファイル全体のトランザクションや、クラウドの永続ストレージは未実装です。バックアップはアプリ停止中に`data/`全体をコピーしてください。

## 検証状況

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

26件の保存・入力検証・進捗・集計・期間境界・検索・タグ・画像コピー・同時保存テストが作成時の環境で成功しています。Pythonソースの構文確認も成功しています。

作成環境ではパッケージ配布先の名前解決ができず、Streamlitをインストールできませんでした。そのため、実際の起動、ブラウザでの見た目、モバイルでの固定ナビゲーション、入力状態、外部ISBN取得の実通信は未確認です。モック画像は目標とするデザインであり、Streamlit標準部品による実装のスクリーンショットではありません。独自HTML・CSS・JavaScriptは追加していません。

起動後は、サンプル読込→ホーム→集計→本→記録編集→保存→検索を確認してください。スマートフォンでは最後の行が固定ナビに隠れないこと、羽ペンボタンから入力できること、キーボード表示時に保存できることを確認してください。
